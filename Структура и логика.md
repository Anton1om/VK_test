# Структура БД
## user
Информация о пользователе, который взаимодействует с VKinder. Параметры из таблицы используются для поиска вариантов для знакомства из других пользователей ВКонтакте

 - vk_id – идентификатор пользователя ВКонтакте
 - age – возраст
 - gender – пол: 1 – женский, 2 - мужской
 - city – город
 

## user_search
Информация о поисках пользователя
 - id – внутренний идентификатор поиска
- user_vk_id – идентификатор пользователя, который искал
- age_from – параметр поиска: возраст от
- age_to – параметр поиска: возраст до
- gender – параметр поиска: пол
- city – параметр поиска: город
- search_date – дата и время выполнения поиска

## user_search_result
Информация о результатах поиска. Предполагаем, что несколько поисковых запросов могут выдавать одного и того же кандидата
- id – внутренний идентификатор 
- user_search_id – идентификатор поискового запроса
- candidate_vk_id – идентификатор кандидита

## candidate
Уникальная информация о кандидатах (пользователи ВКонтакте, которые подошли под заданный критерий поиска). Если информация об одном кандидате повторяется в разных поисковых запросах, то она перезаписывается (то есть один и тот же кандидат сохраняется 1 раз, не дублируется)
 - vk_id – идентификатор кандидата ВКонтакте (используется как ключ)
 - profile_link – ссылка на профиль ВКонтакте
 - name – имя кандидата
 - last_name – фамилия кандидата
 - photos – фотографии (ссылки в формате JSON)
 
Информация о реакции пользователя VKinder на предложенных кандидатов.
## user_interest
- id – внутренний идентификатор
- user_vk_id – идентификатор пользователя
- candidate_vk_id - идентификатор кандидата ВКонтакте
- is_viewed – флаг, что просмотрен пользователем
- is_liked – флаг, что добавлен пользователем в избранное
 
 
# Логика работы программы:
1. Пользователь пишет боту. Бот получает событие с vk_id.
2. Бот через API VK ищет пользователя с таким vk_id и вытаскивает нужные данные (пол, город, возраст). Эти данные сохраняются в user и используются для формирования поискового запроса по умолчанию.
3. Если части информации для поиска не хватает – бот уточняет ее у пользователя и сохраняет в user
4. Перед поиском бот сообщает итоговые параметры поиска (пол - противоположный, город – тот же, диапазон возраста +\- константа от возраста пользователя) и запускает поиск через API VK
5. Информация о поиске сохраняется в user_search (параметры поиска, дата-время поиска)
6. Информация о результатах поисках сохраняется в user_search_result и о новых кандидатах которые появились в результате – в candidate
7. Пользователю выводятся кандидаты в формате:
 
 - имя и фамилия,
 - ссылка на профиль,
 - три фотографии в виде attachment(https://dev.vk.com/method/messages.send).
8. Пользователь может лайкнуть кандидата ( = добавить в избранное), либо пропустить (перейти к следующему). Информация об этом сохраняется в user_interest
9. Если пользователь вышел из бота и зашел заново, то результат следующего поиска фильтруется по кандидатам, которых пользователь уже добавил в избранное \ или просмотрел ранее. На просмотр должны выводиться только новые кандидаты
10. Пользователь по отдельной команде\кнопке может вывести список кандидатов, которые ему понравились (избранные)
11. Пользователь может по команде\кнопке запустить новый поиск (например, если он посмотрел избранных кандидатов и хочет вернуться к поиску)
